# PRレビュー

GitHub上に既に存在するPRの差分とコメントを `gh` で取得してレビューする。

**重要な制約:** PRへのコメント投稿・approve・request changes・merge・close、およびローカルでのcheckout・fetch・ブランチ作成など、状態を変更する操作は一切行わない。行うのはPR情報の読み取り(`gh pr view` / `gh pr diff` / `gh api` のGET)のみ。

## 前提

- `gh` CLI がインストール・認証済みであること。`gh` が無い・未認証・PRが見つからない場合、スクリプトはエラーで終了する。gitでのフォールバック(ブランチ間差分での代用)はせず、エラー内容をそのままユーザーに伝える(未認証なら `gh auth login` を案内する)。
- PRのブランチをローカルにcheckoutしている必要はない。

## 手順

1. **対象PRを確定する**

   - `$target` が PR番号(`123` / `#123`)またはPRのURLならそれを使う
   - 指定が無く「このブランチのPRをレビューして」のような依頼なら、省略して実行する(現在のブランチに紐づくPRを `gh` が検出する。検出できなければエラーになるので、ユーザーにPR番号を確認する)

2. **差分とコメントを取得する**

   同梱の `pr_report.py` を実行する。

   ```
   python ${CLAUDE_SKILL_DIR}/pr_report.py <PR番号またはURL>
   ```

   - カレントディレクトリ以外のGitHubリポジトリのPRを番号で指定する場合: `--gh-repo OWNER/REPO`(URL指定ならURL内のリポジトリが使われるので不要)
   - `gh` を実行するディレクトリ(出力先の基準)を変えたい場合: `--repo <path>`
   - 出力先を明示したい場合: `--output-dir <dir>`

   出力先は `temp/review/{unixtime}_pr{番号}/`(`--output-dir` 指定時はそちら)。差分の分割・`INDEX.md` の生成規則は他のレビュー種別と同じだが、各ブロックの数値列は `original_lines` / `new_lines` ではなく **`additions` / `deletions`(PR差分内の追加・削除行数)** になる。

   あわせて、同じディレクトリに `COMMENTS.md` が必ず生成される。中身はPR本文・会話コメント・レビュー本文・インラインレビューコメント(人間レビュアーとBotの両方。インラインコメントには返信/outdatedの印が付く)。

   - **分割ファイルが1つで済んだ場合**: 標準出力に PRのメタ情報(URL/ブランチ/状態/head・baseのSHA/コメント件数)と差分本文がそのまま出る
   - **分割ファイルが複数生成された場合**: 標準出力には `INDEX.md` と `COMMENTS.md` のパスのみが出る。`INDEX.md` 冒頭にPRのメタ情報がある

3. **PRの意図と既存の指摘を把握する**

   `COMMENTS.md` を読み、PR本文から変更の意図を、コメントから既に指摘・議論されている内容を把握する。コメント件数がすべて0なら、PR本文だけ確認すればよい。

   - 既存コメントで指摘済みの問題を独立に探し直す必要はない。ただし鵜呑みにせず、差分で妥当性を確かめてから採用する(Botの誤検知・outdatedで既に直っている指摘を転記しない)
   - Botの定型文(バッジ・宣伝・自動投稿)は無視する

4. **差分をレビューする**

   他のレビュー種別と同じ観点でレビューする(バグ・既存動作への影響・命名やスタイルの一貫性・テストの有無・意図しないファイルの混入など)。加えて、PR本文に書かれた意図と実際の差分が一致しているかも確認する。

   差分だけでは判断できず、変更ファイル全体の文脈が必要な場合は、ローカルをcheckoutせずに `gh api "repos/{owner}/{repo}/contents/<path>?ref=<headのSHA>" -H "Accept: application/vnd.github.raw"` で読む(headのSHAは標準出力または `INDEX.md` にある)。

5. **結果を報告する**

   - これは既存PR(番号・URL)のレビューであり、PRへのコメント投稿・approve等やローカルのgit操作は一切行っていないこと
   - 差分ファイルと `COMMENTS.md` の出力先ディレクトリのパス
   - 既存コメント由来の指摘を採用した場合はその旨(例:「PR上のレビューコメントより」)
   - `.diffignore` によって除外されたファイルがあれば、その件数

   レビュー結果をPRへ投稿するよう後から求められた場合は、このスキルの範囲外。投稿は他者に見える操作なので、内容をユーザーに確認してから行う。
