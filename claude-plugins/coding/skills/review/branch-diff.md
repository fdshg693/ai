# ブランチ間差分レビュー

現在のブランチ(マージ元)から `$target`(マージ先ブランチ)へPRを出したと**仮定**して、その差分をレビューする。

**重要な制約:** PRの作成・push・merge・checkout・ブランチ作成など、状態を変更するgit操作は一切行わない。行うのは既存の履歴の読み取り(diff)のみ。

## 手順

1. **マージ先ブランチを確定する**

   - `$target` が指定されていればそれを使う
   - 指定がなければユーザーに確認する(推測で決めない)

2. **差分を取得する**

   同梱の `diff_report.py` を実行する。このスクリプトは読み取り専用のgitコマンド(`diff` / `show` / `merge-base` / `rev-parse`)のみを使い、マージ元は指定がなければ自動的に現在のブランチになる。

   ```
   python ${CLAUDE_SKILL_DIR}/diff_report.py <target>
   ```

   - マージ元(現在のブランチ以外)を明示したい場合: `--source <branch>`
   - 対象リポジトリがカレントディレクトリでない場合: `--repo <path>`
   - 出力先を明示したい場合: `--output-dir <dir>`(省略時は下記のデフォルト)

   差分ファイルはパスのアルファベット順に並べたうえで、`temp/review/{unixtime}_{hash(target,source)}/` (デフォルト出力先。`--output-dir` 指定時はそちら)配下に `diff_0001.diff`, `diff_0002.diff`, ... という形で出力される。1ファイルあたり300行を目安に分割されるが、1つの変更ファイルの差分が複数の `diff_XXXX.diff` にまたがることはない(同じファイルの差分は必ず同じ `diff_XXXX.diff` に収まる)。各ブロックには以下が含まれる。

   - ファイルパス(リネームの場合は `旧パス -> 新パス`)
   - status(`A`=追加 / `M`=変更 / `D`=削除 / `R`=リネーム 等)
   - 元ファイルの行数(`original_lines`。merge-base時点の行数。新規追加ファイルは0)
   - 新ファイルの行数(`new_lines`。削除ファイルは0)
   - 差分本文(unified diff)

   出力の分岐は以下のとおり。

   - **分割ファイルが1つで済んだ場合**: 標準出力に差分本文がそのまま出力される。追加でファイルを読みに行く必要はない。
   - **分割ファイルが複数生成された場合**: 各 `diff_XXXX.diff` にどのパス〜どのパスの差分が含まれるかをまとめた `INDEX.md` が同ディレクトリに生成され、標準出力には **この `INDEX.md` のパスのみ** が出力される(差分本文は標準出力に出ない)。この場合は、まず `INDEX.md` をReadして全体像とファイル別詳細(status/行数)を把握し、必要な `diff_XXXX.diff` だけを個別にReadして差分本文を確認する。

   - マージ先・マージ元が同一、または差分ファイルが0件の場合はその旨だけ出力して終了する(異常ではない)
   - マージ先ブランチが存在しない、共通の祖先が無い等の場合はエラーメッセージを出力して終了する。エラー内容をそのままユーザーに伝える

3. **差分をレビューする**

   取得した差分をもとに、通常のコードレビューと同じ観点でレビューする(バグ・既存動作への影響・命名やスタイルの一貫性・テストの有無・意図しないファイルの混入など)。`original_lines` / `new_lines` は、変更の規模感やファイル全体に対する変更割合を把握するために使う。

4. **結果を報告する**

   レビュー結果を報告する際、以下を明記する。

   - これは「`$target` へPRを作成したと仮定した場合」の差分レビューであり、実際にPRは作成していないこと
   - push・merge・ブランチ操作等は一切行っていないこと
   - 差分ファイルの出力先ディレクトリのパス
   - `.diffignore` によって除外されたファイルがあれば、その件数(標準出力または `INDEX.md` に記載される)
