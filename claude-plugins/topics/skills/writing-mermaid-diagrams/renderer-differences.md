# レンダラーごとの差異

> **このファイルは2026-08-10時点のスナップショット。** VS Codeのバージョン・拡張機能の統合状況などは今後も変わる。バージョン番号を含む記述を根拠に判断する前に、疑わしければ`tav-cli`（`tav search`、`mermaid.js.org`や`code.visualstudio.com/updates`へのドメイン絞り込みを推奨）で現在の状態を再確認する。詳細は[SKILL.md](SKILL.md)の「最新情報の取得」節を参照。

Mermaidは1つの仕様に見えるが、実際には「どのMermaid.jsバージョンを積んでいるか」と「どのセキュリティレベルで動かしているか」がレンダラーごとにバラバラで、同じソースでも見え方・動く機能が変わる。原因はほぼこの2つに集約される。

## 原因1: バージョンスキュー

各表示先は最新のMermaid.jsを即座に取り込むとは限らない。Live Editorで書いた最新構文（新しい図種、新しいディレクティブ）が、他の場所では「知らない構文」として無視・崩れることがある。

- **Mermaid Live Editor（[mermaid.live](https://mermaid.live)）**: Mermaid.js本家のリファレンス実装。基本的に比較的新しいバージョンを追随している。**「文法が正しいかどうか」を確認する場所であって、「他の場所でどう見えるか」を確認する場所ではない**点に注意。
- **VS Code**: 2026-05-20リリースのv1.121から、Mermaidレンダリングが組み込み機能「Mermaid Markdown Features」として標準搭載された（従来の`bierner.markdown-mermaid`拡張機能がVS Code本体に統合されたもの）。組み込み後もVS Code自体のリリースサイクルに引きずられるため、Live Editorの最新機能より遅れることがある。
  - **既知の落とし穴**: v1.121以降で`bierner.markdown-mermaid`拡張機能を有効なままにしていると、組み込み機能と競合してMermaidが正しく描画されなくなることが報告されている。VS Codeアップグレード後に急にMermaidが表示されなくなったら、まずこの拡張機能を無効化/アンインストールする。
  - 古いVS Codeを使っている場合は組み込み機能がなく、`bierner.markdown-mermaid`等の拡張機能が必要。
- **GitHub**: PR・Issue・README上の`mermaid`フェンスをGitHub側でレンダリングする。使用バージョンは非公開で、独自のタイミングで更新される。
- **Claude Artifacts**: Markdown Artifactは````mermaid`フェンス、HTML Artifactは`<pre class="mermaid">`で自動レンダリングされる。他レンダラーとバージョンが揃っている保証はない。

**対策**: 枯れた・広くサポートされている構文（`flowchart`/`graph`, `sequenceDiagram`, `classDiagram`, `stateDiagram-v2`, `erDiagram`の基本機能）に留めておけば、バージョン差の影響をほぼ受けない。最新リリースで追加されたばかりの図種・記法を使う場合は、実際に見られる環境すべてで確認するまで「使える」と断定しない。

## 原因2: セキュリティレベルの違い

Mermaidには`securityLevel`という設定があり、`strict`/`loose`/`antiscript`/`sandbox`などのレベルによって「クリックイベントを有効にするか」「ラベル内にHTMLタグを許すか」「`%%{init}%%`ディレクティブでどこまで設定を上書きできるか」が変わる。**第三者が書いたMermaidコードを自動レンダリングする場所は、原則としてセキュリティを厳しめ（`strict`寄り）に倒す**ため、以下のような差が出る。

- **GitHub**: ユーザー投稿コンテンツを表示するため厳しめのセキュリティレベルで動作する。`click`によるインタラクション、ラベル内のHTMLタグ、`%%{init}%%`によるテーマ上書きの一部が効かない/無視されることがある。Live Editorで華やかに見えたカスタムテーマや、ノードクリックでリンクに飛ぶ機能が、GitHub上では反映されない前提で作る。
- **Mermaid Live Editor**: 自分で設定を操作できるため、`loose`寄りの挙動を確認しやすい。ここで動いたからといって、GitHub/VS Codeで同じように動くとは限らない。
- **VS Code / Claude Artifacts**: それぞれ独自の設定でMermaidを呼び出しており、GitHubほど厳しくない場合もあるが、当てにせず個別に確認する。

**対策**: 複数の場所（特にGitHub）で見られることが分かっている図では、`click`イベントやラベル内HTML、凝った`%%{init}%%`テーマ上書きに依存しない。見た目の調整は`classDef`/`style`のような標準的な仕組みに留める。

## まとめ: 迷ったときの判断基準

| 状況                                                     | 判断                                                                                                                                                                                                     |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1箇所（例: 自分のVS Codeプレビューのみ）でしか見られない | そのレンダラーで実際に確認すればよい。過度に慎重になる必要はない                                                                                                                                         |
| GitHub PR/README等、複数人・複数環境で見られる           | 枯れた構文に留め、`click`/HTML labels/カスタムテーマに依存しない                                                                                                                                         |
| 見たら崩れていた                                         | まず「バージョンスキュー」か「セキュリティレベル」のどちらが原因か切り分ける。次に別レンダラー（[mermaid.live](https://mermaid.live)が一番情報が集めやすい）で同じソースを試し、崩れが再現するか確認する |
