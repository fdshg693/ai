# use-context スキルについて

`tools/ctx7/`の`ctx7` CLI(Context7 REST APIを`requests`で直叩きする自作ラッパー)を、
Claudeが会話の中からすぐ使えるようにするためのスキル。このファイルは人間のメンテナ
向けで、設計意図と前提条件を説明する。Claudeが実行時に読むのは
[SKILL.md](SKILL.md)であり、こちらは参照しない。

## なぜこのスキルがあるか

- Context7には公式の`context7-mcp`スキル・`docs-researcher`エージェント・
  `/context7:docs`コマンドが既に存在する。このスキルはそれらを置き換えるのではなく、
  「いつContext7を使うか」「`ms-learn`とどう使い分けるか」「候補IDをどう選ぶか」
  「複数論点をどう分割するか」「長い調査をメイン会話からどう分離するか」「公式機能と
  二重発火させないためのルーティング」といった、CLI自体の仕様には現れない**運用上の
  判断**を固定化するために作った
- CLI本体(`ctx7`)はMCPを介さずContext7のREST API(`https://context7.com/api/v2/...`)を
  直接叩く実装で、MCP接続では難しいクエリ整形・出力形式のカスタマイズ・`jq`等の後段
  CLIへのパイプができる。この判断の経緯は`.claude/plans/use-context/01-research.md`
  (Step1の事前調査結果)を参照

## 前提条件(重要)

- `ctx7`コマンドは事前にインストール済みであること
  (`uv tool install --editable tools/ctx7`)。このスキルはインストール処理を一切
  行わず、CLI本体も同梱しない
- Context7のAPIキー(`CONTEXT7_API_KEY`)は**任意**。未設定でも動作するが、レート
  制限が低くなる(実機確認済み。詳細は`tools/ctx7/README.md`の「認証」参照)
- 上記が満たされていない環境(未インストール)でこのスキルが呼ばれた場合、Claudeは
  このスキルではエラーに対処せず、`tools/ctx7/README.md`のセットアップ手順を
  ユーザーに案内する

## 情報源と保守

- CLI本体の設計意図・実装メモ・ファイル構成の一次情報は`tools/ctx7/README.md`
- サブコマンド・オプション・出力形式・終了コードの一次情報も`tools/ctx7/`配下
  (`ctx7_cli.py`本体)だが、SKILL.mdはClaudeが実行時に外部ファイルへジャンプしなくて
  済むよう、意図的に自己完結する形で複製している。CLIのオプション名・出力形式・終了コード
  が変わった場合はSKILL.mdも合わせて更新すること
- 判断フロー・クエリの具体化のコツ・`ms-learn`との使い分け・公式スキルとの棲み分けは
  このスキル固有の運用方針であり、`tools/ctx7/README.md`には存在しない

二重化した内容のドリフトを防ぐため、CLI仕様を変更するときは次の順で確認する。

1. `tools/ctx7/README.md`および`ctx7_cli.py`を正本として、CLI本体と仕様を更新する
2. `SKILL.md`の「サブコマンド」「終了コード」を同じ変更内容に更新する
3. オプション名・出力形式・終了条件を両ファイルで突き合わせる
