## 全体の流れ

```markdown
1. mslearn search "<query>" / code-search "<query>" [--language <lang>] を実行する
   → 結果フォルダの index.md パスだけが返る(個別ファイルのパス・本文はここでは
   分からない)

2. index.md を Read し、結果ファイルへの相対リンク一覧(タイトル・各件の文字数付き)を
   把握する(フォルダ直下 = 公式ドキュメント、qa/ 配下 = Microsoft Q&A)。ここで
   aim に渡す対象を決める:
   (a) タイトルだけでは関連性が判断しづらい・件数が多い(目安5件以上) → 全件を渡す
   (b) すでに読みたいファイルはタイトルから絞れている → その中で文字数が大きい
   ものだけを渡す(小さいものはそのまま個別に Read すればよく、このスキルは
   使わない)

3. 元の質問/知りたいことを1本の「抽出プロンプト」に言語化する(下記「抽出プロンプトの
   作り方」参照)。ファイルごとに指示を変える必要は通常ないので、同じ抽出文を各
   `--prompt` に繰り返す。ファイル名や個々のタイトルはプロンプトに埋め込まない

4. 手順2で選んだファイルがおおよそ5件以上ある場合のみ、本実行の前に1件だけを
   `aim --prompt "<抽出プロンプト> @<1件のパス>"`で投げ、エラーなく応答が返ることを
   確認する(モデル側の問題を全件投入前に切り分けるため。下記「注意点」参照)。3〜4件
   規模ならスモークを省略して手順5へ進む（1件テスト+本番で実質+1回になり、損失が同じ）

5. 手順2で選んだ結果ファイルパスを、ファイルごとに1つの `--prompt` として"まとめて1回"aimに渡す
   aim --parallel --jobs <並列数> --prompt "<抽出プロンプト> @<folder>/0001.md" "<抽出プロンプト> @<folder>/0002.md" ...
   → 1コマンドで選んだ結果への並列AI呼び出しが走り、ファイルごとの応答が返る。
   Claude自身が個別ファイルをReadする必要はない

6. aimの応答を見て、「関連なし」以外の項目だけをユーザーへの回答に統合する。
   抽出プロンプトに「URL:/Link:行があれば転記して」と指示しておけば、出典URLも
   追加のReadなしで拾える(`search` / `fetch` とも各結果ファイルの冒頭に
   `URL:` 行があり、`code-search` は `Link:` 行)

7. 抜粋だけでは情報不足な場合だけ、該当ページを mslearn fetch <URL> でフルページ取得し、
   必要なら同じ要領でaim(1ファイルのみでも可)に該当箇所を抽出させる
```

手順1・2・7は `ms-learn` スキル(`claude-plugins/my-tools/skills/ms-learn/SKILL.md`)と
完全に同じ挙動。オプション・出力フォルダ仕様・終了コードなどの詳細はそちらを参照し、
ここでは重複させない。

## 抽出プロンプトの作り方

`--parallel` はプロンプトごとに独立した指示を使える。抽出では同じ指示を各 `--prompt`
に繰り返すのが基本（ファイルごとに変えなくてよい）。「何を探しているか」をファイル
非依存の形で言語化するのがコツ。指示と対象 `@path` を1プロンプトにまとめて、ファイル
の数だけ並べる。

例: ユーザーの質問が「Azure Functions の Python v2 モデルでタイムアウトを変更する方法」の場合

```text
以下はMicrosoft公式ドキュメントの検索結果の抜粋です。
「Azure Functions の Python v2 プログラミングモデルでタイムアウト時間を変更する方法」
に関連する記述があれば、該当箇所を日本語で簡潔に抜き出してください。
冒頭付近の `URL:` または `Link:` 行があれば、それも回答の末尾にそのまま転記してください。
関連する記述が無ければ、他には何も書かず「関連なし」とだけ答えてください。
```

- ❌ 単に「要約してください」だけだと、無関係な結果まで律儀に要約されてしまいフィルタ
  リングにならない。**「関連が無ければ関連なしとだけ答える」を必ず明示する**
- 抜粋が「詳しくは...を参照」のように途中で切れているなど、情報が不十分そうな兆候を
  拾いたい場合は、抽出プロンプトに「情報が不十分そうなら『要フルページ取得』と付記して」
  も足しておくと、手順7に進むべきファイルをaimの応答だけから判断できる
- `code-search` の結果に対しては「探しているコードパターン/実装したい処理」を軸に
  同様のプロンプトを組み立てる

## 並列数(`--jobs`)の目安

- `search`結果は既定で最大10件前後(docs+qaを合わせるとさらに増える)。`aim --parallel`の既定
  `--jobs 4`でも十分速いが、件数が多い/急ぎなら`--jobs 8`〜`10`(上限)まで
  上げてよい。`--jobs`は`--parallel`専用
- 複数クエリの結果フォルダをまたいで一括処理したい場合も、全ファイルを1回の
  `aim --parallel`呼び出しに `--prompt` として並べて渡せば同様に並列化される
- `--jobs`を上げても速くなるのはAI呼び出しが正常に進む場合のみ。既定モデルが
  利用不可などモデル/API側に問題がある場合は全ファイルが同じエラーで即失敗するだけ
  なので、件数がおおよそ5件以上のときだけ「注意点」の1件スモークテストで切り分ける。
  少数なら本実行の失敗を見て`--model`を切り替える

## 使い分け: このスキル vs `ms-learn` スキル

| 状況                                                                                        | 使うスキル                                |
| ------------------------------------------------------------------------------------------- | ----------------------------------------- |
| 結果が1〜2件で、内容もすぐ読める規模                                                        | `ms-learn`(直接Readした方が単純)          |
| index.md でタイトルから選んだファイルが小さい(文字数が少ない)                               | `ms-learn`(そのまま個別に Read)           |
| 件数が多くタイトルだけでは関連性を判断しづらい(目安5件以上)、複数クエリ分をまとめて捌きたい | `ms-digest`(このスキル・全件投入)         |
| index.md で選んだファイルの中に文字数が大きいものが複数ある                                 | `ms-digest`(このスキル・選んだ分だけ投入) |
| すでに対象URLが分かっていて全文フェッチだけしたい                                           | `ms-learn`の`fetch`をそのまま使う         |

いずれの場合も判断は必ず `index.md` を Read した後に行う(mslearn 実行直後に返るのは
`index.md` のパスのみで、集計値は返らない)。「大きい」の閾値は会話の残りコンテキスト量
や個別ファイルの内容次第で変わるため固定値はなく、index.md に付記された各ファイルの
文字数を見て都度判断する。

## 注意点

- `aim --parallel`はステートレスでDB永続化はしない。同じ検索をやり直す場合は都度呼び直す
  ことになる(mslearn側の結果ファイル自体は使い捨てフォルダに残るため再利用は可能)
- 個別ファイルの読み込み失敗・AI呼び出し失敗は、そのプロンプトだけ失敗として記録され
  他ファイルの処理は継続する(`aim-cli`スキル参照)。失敗したファイルは`mslearn fetch`
  など代替手段で個別に読む
- `mslearn`/`aim`双方のインストール手順・環境変数・終了コードなどのセットアップ/
  仕様はこのスキルでは扱わない。未設定エラーが出た場合はそれぞれのスキルの案内に従う
- **全ファイルが同一のエラーメッセージで失敗した場合は、個別ファイルの問題ではなく
  モデル/API側の問題を疑う**(例: 既定の無料枠モデルが提供停止でOpenRouter呼び出しが
  全滅する、など)。この場合は手順7の個別フォールバック(`mslearn fetch`)に進んでも
  無意味なので、`--model`に別のモデル略記(`aim --list-models`参照)を明示して
  全件を再実行する
