# `agent`(Cursor CLI)対話モードを繋ぐ場合

[SKILL.md](SKILL.md)の汎用手順を前提に、Cursor CLI(`agent`、`-p`を付けない対話モード)固有の実地検証結果をまとめる。他の対話CLIには当てはまらない可能性がある(トイCLI相手の検証だけでは見えなかった、この特定CLI固有の挙動)。

## 既知の癖

1. **起動直後は約15〜20秒の初期化猶予期間を空けてから最初の`send`を行う**。`icw start`が返す最初の画面(バナー+プレースホルダ)は見た目上「入力待ち」だが、この直後に送信してもEnterが反応しない(入力欄にテキストが残ったまま無反応になる)。このコストは初回送信前だけの一度きりで、2ターン目以降は不要。
2. **`icw send`に`--submit-separately`を付ける**。既定の送信方式(入力テキストと改行を1回の書き込みにまとめる)は、`agent`の生キー入力処理では「複数行の貼り付け」とみなされてしまい、Enterとして扱われない。`--submit-separately`はテキストと送信キーを別々の書き込みに分けて送る(既定の`--submit-key`はCRのみ、`--submit-delay`は0.3秒)。
3. **`--ready-pattern`は指定せず、idle-timeoutのみに頼る**。入力欄が空のときに常時表示されるプレースホルダ文字列(`Add a follow-up`等)は、生成中(`Working`表示中)でも表示され続けるため、確実な`ready_pattern`にならない。

## コマンド例

```bash
# 起動(workspace trustダイアログを--trustで自動許可。未trustのworkspaceで--trustを付けない場合は
# 起動直後の画面にtrustダイアログが出るので、"a"のような1文字を送って通過させる)
icw start --session agent1 --idle-timeout 2 --overall-timeout 45 -- agent --trust --workspace <作業ディレクトリ>

# 最初のsendの前に15〜20秒程度待つ(例: sleep 18)。2ターン目以降はこの待機は不要
icw send --session agent1 --idle-timeout 3 --overall-timeout 120 --submit-separately "<最初のメッセージ>"

# 2ターン目以降は待機不要
icw send --session agent1 --idle-timeout 3 --overall-timeout 120 --submit-separately "<次のメッセージ>"

icw stop --session agent1
```

`overall_timeout`は実際のタスク内容(ツール呼び出しの有無)次第でモデル応答が数十秒〜それ以上かかりうることを見込んで長めに取る。

## 詳しい調査過程

症状は「`icw send`で送信したメッセージが一切反応しない」(idle-timeoutを1〜30秒まで変えても同じ)で、バナーが変化せず会話履歴も増えないことから「まだ生成中」ではなく「送信自体がされていない」ことが分かった。切り分けで実際に検証し、**原因ではない**と確認済みの仮説:

1. **テキストとEnterの間の待機時間が足りない** — 0.3〜3.0秒まで変えても、他条件が揃っていなければ全て失敗した。待機時間の長さは無関係。
2. **`--trust`フラグでtrustダイアログをスキップしていることが原因** — 既にtrust済みのworkspaceに対して`--trust`無しで起動しても(ダイアログ自体が出ない)、依然として送信は失敗した。`--trust`の有無は無関係。
3. **`send()`の既定(`text + "\r\n"`を1回の`write()`)は、起動グレース期間さえ空ければ動く** — 18秒待ってから既定の`send()`を呼んでも失敗した(入力欄に2ターン分のテキストが改行で連結されたまま残った)。グレース期間だけでは不十分。

確定した原因は、上記「既知の癖」1・2の**2条件の組み合わせ**(どちらか一方だけでは失敗する)。詳細は[tools/interactive-cli-wrapper/README.md](../../../../tools/interactive-cli-wrapper/README.md)の「`agent`対話モードへの接続で判明した癖」節も参照。

## cursor-cli-use(非対話)との使い分け

| 観点                     | このスキル(`interactive-cli-wrapper`)                      | cursor-cli-use                                                                |
| ------------------------ | ---------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 対象CLIモード            | 対話(REPL)モード全般                                       | Cursor CLI(`agent`)の非対話(`-p`/`--print`)単発実行のみ                       |
| 会話の継続性             | 同一セッション内で複数ターンの文脈を保てる                 | 1回の呼び出し=1回の完結したタスク。継続は呼び出し側で都度`agent -p`を叩き直す |
| 対象CLIの範囲            | `agent`に限らず、TTY前提のREPL型CLI全般                    | `agent`専用                                                                   |
| 起動・チューニングの手間 | セッション起動・待機・ready検知調整など、対象CLIごとに要る | `agent -p --force --model <id> "<prompt>"`だけで完結、調整不要                |

**単発のタスク委譲(ファイル生成・調査等を1回投げて結果だけ欲しい)なら、まずcursor-cli-useを検討する。** 対話履歴を保った複数ターンのやり取り、スラッシュコマンド操作など、非対話フラグでは表現できない使い方が必要なときだけこのスキルを使う。
