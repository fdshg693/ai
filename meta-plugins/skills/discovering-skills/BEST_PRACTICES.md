# discovering-skills: よくあるタスクパターン早見表

`skill-search`エージェントを毎回呼ばずに済むよう、このリポジトリでよく発生するタスク形状と、その際に組み合わせるべきスキル群をあらかじめまとめた早見表。SKILL.md本体の手順2（skill-searchエージェント呼び出し）より前に確認する。

## 使い方

1. **まず「必須級スキル」（下記）に該当する要素がタスクに含まれていないか確認する。** 該当すればパターン判定を待たずに採用候補へ加える。
2. タスクがここに載っているパターンのいずれかに合致するか確認する。合致すれば該当パターンファイル（`patterns/*.md`）を読み、指示されたスキルをTODOに組み込む（SKILL.md本体の手順4以降と同じ要領）。
3. 合致するパターンがない、またはパターンに載っているスキルだけでは不足していると感じたら、通常通り`skill-search`エージェントに検索を依頼する（SKILL.md本体の手順2）。
4. パターンに載っているスキル名が実在するかは、使う前にGlobで一発確認する（リネーム・削除されている可能性があるため）。
5. 同じ形のタスクが繰り返し発生していると気づいたら、このファイルと対応するパターンファイルを追記して育てる。

## 必須級スキル（パターン判定より先に確認する）

タスクの一部にでも以下の要素が含まれるなら、どの`パターン一覧`に合致するか迷う前に、まずここを確認する。**generic な`WebSearch`/`WebFetch`ツールを素で使う前に必ず目を通す**（タスク全体の主目的が別のパターン、例えば「スキル新規作成」であっても、その中の一部の手順がここに該当することがある）。

| 該当する要素                                                                                                                                                                               | まず検討するスキル                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Web検索・外部ページの取得が少しでも絡む（1URLの中身を見る、キーワードで探す、複数ページ集める等）                                                                                          | `tav-lit`（既知1URLの本文取得）/ `tav-cli`（検索・複数URL・サイトmap/crawl）/ `tav-digest`（`--topic`で集めた複数ページの絞り込み）。Microsoft/Azure公式なら`ms-learn`/`ms-digest`、AWS公式なら`aws-docs`、GCP と Google Workspace の開発者向け公式ドキュメントなら`gdev-docs`、それ以外のライブラリはドキュメントなら`use-context`、配布物の中身なら`inspecting-python-libraries`が優先（詳細は[patterns/external-doc-research.md](patterns/external-doc-research.md)） |
| ライブラリの配布物・実装・公開モジュールを一次ソースとして読む（wheel の中身、実際の公開面）                                                                                               | `inspecting-python-libraries`（`pyinspect`）。ドキュメント・移行ガイドなら`use-context`、他リポジトリの実使用例なら`grep-app`（詳細は[patterns/external-doc-research.md](patterns/external-doc-research.md)）                                                                                                                                                                                                                                                            |
| このリポジトリでコミットする（`git commit`、フック失敗、何をステージするか）                                                                                                               | `committing`（`meta-plugins/skills/committing/SKILL.md`）。再生成・整形はlefthookに任せ、同じコマンドを手で先実行しない                                                                                                                                                                                                                                                                                                                                                  |
| `SKILL.md`または`tools/`配下のCLIを変更する                                                                                                                                                | `changing-skills-and-tools`。変更対象を決めてから`skill-tool-impact`で下流スキル・ツールを確認する。対象が無ければ不要な全体グラフ読込はしない                                                                                                                                                                                                                                                                                                                           |
| このリポジトリ自身のメンテ規約に触れる（`tools/`配下に新規スクリプト・CLIを足す、`repo-tools.yaml`/`ai-tools.yaml`等のSSOTを触る、lefthook/justfileを足す、版数・`--version`・`.env`規約） | `meta`（`meta-plugins/skills/meta/SKILL.md`）。`docs/repo-wide/*.md`の一覧から該当する規約ドキュメント1件へ振り分ける。その場で新しい判断ロジックを書かない（`tools/`配下のCLI実装そのものは[patterns/repo-tool-building.md](patterns/repo-tool-building.md)）                                                                                                                                                                                                           |
| このリポジトリの全体像・どこに何があるか（初見、未知のディレクトリ、概要を先に取りたい）                                                                                                   | `exploring-this-repo`（`meta-plugins/skills/exploring-this-repo/SKILL.md`）。広い `codegraph explore` は使わない。スキル本文なら `discovering-skills`、メンテ規約なら `meta`                                                                                                                                                                                                                                                                                             |

**実例（2026-08-10）**: 「Mermaidスキルを新規作成する」タスクで、レンダラーの最新挙動をWeb検索する場面があった。タスク全体は`スキル新規作成・改修`パターン（[patterns/skill-authoring.md](patterns/skill-authoring.md)）に合致していたため、そちらの確認で満足してしまい、タスクに埋め込まれた「外部ドキュメント調査」の側面（本来は`tav-lit`/`tav-cli`を検討すべきだった）を見落とし、素の`WebSearch`ツールを直接使ってしまった。複数パターン・複数要素にまたがるタスクほどこの見落としが起きやすいので、パターン判定の前に必須級スキルの表を必ず確認する。

## 注意

- ここに載っているのは「よく発生する」パターンのみで網羅ではない。載っていない形のタスクは素直に`skill-search`へ進む。
- 1つのタスクが複数パターンにまたがることもある（例: 新規スキルを書いてから他ツールに横展開する）。その場合は該当パターンを両方読む。
- パターンファイルの粒度は「タスクの形」単位であり、個別スキルの使い方そのものは書かない（それは各スキルのSKILL.md本体の責務）。
- 「必須級スキル」の表も網羅ではない。パターンに関わらず繰り返し見落とされている要素に気づいたら、この表に追記して育てる（運用はパターン一覧と同じ）。
