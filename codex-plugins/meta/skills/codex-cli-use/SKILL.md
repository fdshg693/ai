# Codex CLI 非対話実行

OpenAI Codex CLI（`codex`）へ、単発のコーディング・レビュー・調査タスクを委譲する。対象は、完了まで人間との対話を必要としない `codex exec` である。通常の対話セッション、CLIフラグの網羅的な調査、Codexの最新仕様の説明はこのスキルの対象外とする。

委譲するタスク: $ARGUMENTS

## 実行前の確認

次を実行して、CLIのインストールと認証状態を確認する。

```powershell
codex --version
codex login status
```

`codex` が見つからない場合は、Codex CLIのインストールを案内する。未認証の場合は、対話ログインなら `codex login`、自動化ならAPIキーを標準入力から渡す `codex login --with-api-key` を案内する。APIキーやアクセストークンをプロンプト、ログ、コマンドライン引数へ埋め込まない。

認証方法・料金・機能制限の最新情報は、必要に応じて `codex-docs` の公式ドキュメントを参照する。

## モデル選択

タスクを次の2種類に分類し、原則として明示的に `--model` を指定する。

| タスクの性質                                                                 | モデルID       |
| ---------------------------------------------------------------------------- | -------------- |
| ほとんどの実装、調査、レビュー、定型作業                                     | `gpt-5.6-luna` |
| 高度な推論が必要な設計判断、難しいバグ、セキュリティ、正確性が最重要のタスク | `gpt-5.6-sol`  |

通常は `gpt-5.6-luna` を使い、`gpt-5.6-sol` は本当に高度な推論が必要な場合だけ使う。モデルIDが利用できないエラーになった場合だけ、次で現在のモデルカタログを確認して、利用可能なIDへ置き換える。

```powershell
codex debug models
```

## 権限とサンドボックス

自動実行では、作業内容に応じて最小限の権限を指定する。

- 読み取り・要約・レビュー: `-s read-only`
- ワークスペース内の実装: `-s workspace-write`
- `danger-full-access`: 原則として使わない。外部から完全に隔離された専用ランナーで、かつ明示的な要件がある場合だけ検討する

非対話実行で承認待ちにしない場合は、グローバルオプションをサブコマンドより前に置いて `-a never` を指定する。

```powershell
codex -a never exec -s read-only -m gpt-5.6-luna "リポジトリを調査し、問題点と修正案だけを報告してください。ファイルは変更しないでください。"
```

`--dangerously-bypass-approvals-and-sandbox` は承認とサンドボックスを無効化する非常に危険なオプションである。通常のローカル作業では使わない。作業範囲を広げる必要がある場合は、まず `--add-dir <DIR>` で必要なディレクトリだけを追加する。

書き込みタスクでは、プロンプトにも「変更対象」「変更禁止範囲」「実行してよい検証」「デプロイしないこと」を明記する。変更後は呼び出し元で差分とテスト結果を確認する。

Codex自身も、`-a never -s workspace-write` 下であっても、外部サービスへの実送信やAPI課金を伴うコマンド（例: 実装した機能を使って本物の外部AI呼び出しを試す等）は自律的に実行を拒否し、モック・dry-run相当の検証に切り替えて完了報告することがある。これはCodex側の安全側の判断であり、承認待ちで停止しているわけではない。課金・外部送信を伴う検証まで実行させたい場合は、プロンプトで明示的に許可し、その範囲を限定する。逆に許可しない場合は「実際の外部呼び出しは行わず、モック/dry-runでの検証に留めること」と明記しておくと、Codexが自己判断で止まった理由が報告から追いやすくなる。

## 基本コマンド

### 読み取り専用の調査

```powershell
codex -a never exec `
  -C . `
  -m gpt-5.6-luna `
  -s read-only `
  --ephemeral `
  "対象コードを調査してください。ファイルを変更せず、根拠となるファイルパスと行番号、推奨対応を簡潔に報告してください。"
```

`--ephemeral` はセッションファイルを保存しない。機密性や再開不要の一回限りの調査で使う。

### ワークスペース内の実装

```powershell
codex -a never exec `
  -C . `
  -m gpt-5.6-luna `
  -s workspace-write `
  -o $env:TEMP\codex-last-message.txt `
  "要求を実装してください。変更はこのワークスペース内に限定し、既存のルールを確認してください。完了後に変更ファイル、実行した検証、未解決事項を報告してください。デプロイは実行しないでください。"
```

`-o`（`--output-last-message`）の出力先は、作業対象リポジトリの直下ではなくスクラッチ領域（一時ディレクトリ等）にする。リポジトリ直下に書くと、タスク完了後に `git status` へ未追跡ファイルとして残り、後片付けが1手間増える。

長いプロンプトやPowerShellの引用符が複雑な場合は、標準入力から渡す。

```powershell
$prompt = @'
次のタスクを実装してください。
- 変更範囲: src/ 配下のみ
- 検証: 既存のテストを実行する
- 禁止: デプロイ、秘密情報の表示、src/ 外の変更
- 最後に変更ファイルと検証結果を要約する
'@
$prompt | codex -a never exec -C . -m gpt-5.6-luna -s workspace-write -
```

リポジトリ外で実行する必要がある場合だけ、タスクの意図を確認したうえで `--skip-git-repo-check` を追加する。無関係なディレクトリを `-C` や `--add-dir` に指定しない。

## 出力と再利用

- 人間が読むだけなら、既定の整形済みテキストを使う
- 後続処理で扱うなら `--json` を使い、標準出力のJSONLイベントを保存する
- 最終回答だけをファイルへ保存するなら `-o, --output-last-message <FILE>` を使う
- CIでは `--json` と `--output-last-message` を併用し、進捗イベントと最終要約を分離する

```powershell
codex -a never exec -C . -m gpt-5.6-luna -s read-only --json -o $env:TEMP\codex-last-message.txt "テスト結果を調査し、失敗原因を報告してください。"
```

同一タスクを続きから実行する必要がある場合は `codex exec resume` のヘルプを確認してから使う。単発委譲を繰り返すだけなら、呼び出し元で必要な回数だけ `codex exec` を実行し、プロンプトに入力・出力契約を明示する。

## 実行時間とバックグラウンド実行

小さめの差分だけのタスクは数分で終わるが、Codexが自分で検証スクリプト（モックテスト、リンタ実行など）を書いて反復すると、単純な差分量から想像するより時間がかかる（10分を超えることも珍しくない）。呼び出し元のツールに同期実行のタイムアウトがある場合は、次のいずれかを取る。

- あらかじめ長めのタイムアウトを設定する
- 完了を待つ必要がなければ、最初からバックグラウンド実行にして完了通知を待つ

タイムアウトで打ち切られても `codex exec` プロセス自体が失敗するわけではない（バックグラウンドに移行するだけのことが多い）ため、慌てて同じタスクを再投入しない。出力ファイル（`-o` の指定先やリダイレクト先）を確認すれば、完了しているかどうか判断できる。

## 委譲プロンプトの要件

最低限、次の内容をプロンプトに含める。

1. 目的と完了条件
2. 対象ディレクトリ・変更可能なファイル
3. 読み取り専用か、書き込みを許可するか
4. 実行してよいテスト・コマンド
5. 禁止事項（デプロイ、破壊的操作、秘密情報の表示など）
6. 最終報告に含める項目（後述の「呼び出し元でのコンテキスト節約」参照）
7. API課金・外部送信を伴う検証を許可するか（既定は不許可とし、モック/dry-runに留めさせる）

Codex CLIは作業ディレクトリの `AGENTS.md` やプロジェクトルールを読むことがある。委譲元のルールと重複したログ・成果物が生成されないよう、必要ならプロンプトで「指定したタスク以外のファイル作成・変更をしない」と明示する。ただし、プロジェクトのルールを無視するよう指示する場合は、無視してよい範囲を具体的に限定する。

## 呼び出し元でのコンテキスト節約

Codexへの委譲は、委譲元エージェント自身のコンテキストを節約する目的で使うことが多い。次の2点を徹底すると効果が大きい。

- プロンプトの末尾で、最終報告のフォーマットを固定して要求する（例:「変更/作成したファイル一覧」「実施した動作確認とその結果」「プランや指示からの逸脱点とその理由」「未解決事項・次に注意すべき点」）。これにより、呼び出し元はCodexの試行錯誤の過程を読まずに、末尾の要約だけで次の判断ができる。
- Codexの標準出力が大きい場合、呼び出し元のツール（Bash/PowerShell）が全文をファイルへ退避して先頭だけを見せることがある。その場合は全文を読み直さず、退避先ファイルの末尾（`tail` や `Get-Content -Tail`）だけを取得すれば、上記の最終報告部分を安く回収できる。

## 詳細仕様の調査先

CLIのフラグ、サブコマンド、引数、サンドボックス、承認ポリシーを確認する必要がある場合は、次の順で調べる。

1. `.agents/skills/codex-cli-docs/SKILL.md` を使い、実環境の `codex --help` または `codex <subcommand> --help` を根拠にする
2. 認証、設定、料金、最新の仕様や概念は `.agents/skills/codex-docs/SKILL.md` を使い、公式ドキュメントを参照する
3. このスキルの古い例と実環境のヘルプが食い違う場合は、実環境のヘルプを優先し、必要ならこのスキルの例を更新する

このスキルは、詳細仕様を記憶だけで補わない。特に危険な権限オプションは、実際のヘルプに記載された警告と現在の利用可能な値を確認してから案内する。
